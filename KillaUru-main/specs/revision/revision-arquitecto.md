# Revisión de consistencia arquitectónica — KillaUru (specs 001–007)

> Revisor: arquitecto de software senior · Fecha: 2026-10-21 · Trabajo de solo lectura
> Raíz: `KillaUru-main/` · Fuente de verdad: `referencia/docs/` · Constitución: `.specify/memory/constitution.md`
> Rutas abreviadas: `docs/` = `referencia/docs/`; `enfoque` = `docs/02-arquitectura-de-software/enfoque-arquitectonico.md`; `componentes` = `docs/02-…/componentes-arquitectonicos.md`; `diseño-interno` = `docs/03-diseño-de-software/diseño-interno-de-modulos.md`; `NivelN` = `docs/04-modelo-C4/NivelN-….md`. Las specs de `specs/` son idénticas en la raíz y en el worktree `specs-005-007` (verificado con `diff -rq`).

## Resultado general

| Punto revisado | Resultado |
|---|---|
| 1. Constitución vs docs y Constitution Check | La constitución es fiel a docs salvo dos matices (ARQ-20, ARQ-24). Los Constitution Check marcan ✅ el principio I aunque varias specs **contradicen** docs y la constitución exige corregir docs primero (ARQ-05). La prueba del límite de 200 líneas no cubre todo lo que la constitución pide (ARQ-04). |
| 2. Grafo de dependencias | **Correcto.** Referencias `.csproj` de cada plan: Auditoría→Shared; Identidad→Shared, Auditoría; Anomalías→Shared, Auditoría; Ingesta→Shared, Anomalías; Mapa→Shared, Anomalías; Dashboard→Shared, Anomalías, Identidad. Coincide exactamente con `componentes` regla 4 (línea 204). Sin ciclos. Único desvío documental: el consumidor «API REST» de `IAuditoriaService` (ARQ-11). |
| 3. Contratos públicos | 11 diferencias de nombre o firma (ARQ-05, ARQ-14, ARQ-15, ARQ-16). La mayoría son mejoras justificadas que docs aún no recoge. |
| 4. Capas, Options y nombres | Las 5 `<Modulo>Options` están donde dice `enfoque` §5 (Anomalías en Domain; Ingesta, Identidad, Dashboard y Mapa en Application). **Violaciones de capa:** Adapters→Domain (ARQ-01) y Domain→Contracts de otro módulo (ARQ-02). Nombre de repositorio cambiado (ARQ-06). |
| 5. Árboles de archivos | 5 archivos con riesgo claro de superar 200 líneas (ARQ-08); faltan puertos y repositorios de lectura en 004 (ARQ-07). |
| 6. Cobertura de docs 02/03 | Sin spec: publicación de contenido en R2 (ARQ-21), auditoría de accesos del host (ARQ-11), ajuste de pool/PostgreSQL (ARQ-22). Alcance: app Android y panel sin specs (ARQ-23). |
